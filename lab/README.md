# HealthHub AI — обновлённая учебная система

Полноценный учебный прототип веб-приложения с адаптивной мобильной версией. Реализация основана на исходном задании HealthHub AI: единый REST API, PostgreSQL, роли пациента/врача/администратора, мониторинг показателей, медицинские события и визуальная панель.

> **Важно:** HealthHub AI — учебный прототип, не медицинское изделие, не ставит диагнозы и не назначает лечение. Все предустановленные данные вымышлены. Не загружайте реальные медицинские данные.

## 1. Что реализовано

### Интерфейс
- Компоновка в стиле предоставленного концепта: тёмная боковая навигация, светлая рабочая область, карточки, графики и блоки Dashboard.
- Адаптивная мобильная вёрстка: меню превращается в выдвижную панель, карточки и таблицы перестраиваются под узкий экран.
- Обновлённая SVG-визуализация человеческого тела: цельный силуэт, градиентная заливка, маркеры зон мониторинга.
- Экран авторизации, профиль пользователя и отображение роли.
- Девять разделов навигации: Главная, Мои показатели, Записи к врачу, Анализы, Медкарта, Уведомления, Рекомендации, ИИ-ассистент, Настройки.

### Данные и сценарии
- Авторизация через JWT; пароли демонстрационных пользователей хранятся как scrypt-хеши.
- Показатели: пульс, SpO₂, температура, шаги, сон.
- Добавление, просмотр, изменение и удаление измерений. Значение и единица измерения валидируются на сервере. После успешного ответа API список и Dashboard обновляются из PostgreSQL.
- Фильтр истории: сегодня, 7, 30 и 90 дней.
- Серверная аналитика: среднее, минимум, максимум и количество измерений.
- Список врачей и клиник, свободные временные слоты, создание записи, отмена, подтверждение/завершение и перенос на свободный слот.
- Анализы с детализацией результатов и референсными интервалами; загрузка и скачивание PDF/PNG/JPEG-документов (до 5 МБ).
- Медицинская карта с категориями и хронологическими записями.
- Рекомендации с действиями «Выполнить», «Отложить», «Скрыть».
- Уведомления с отметкой прочтения.
- ИИ-ассистент на заранее подготовленных правилах; история сообщений сохраняется в PostgreSQL только при явном согласии пользователя.
- Экспорт измерений в CSV.
- Серверные проверки ролей и прав доступа; врач видит записи пациентов только при активном разрешении `access_grants`; администратор не получает автоматического доступа к содержимому медицинской карты и чатов.

### Структура базы данных
В `server/schema.sql` описаны Users, PatientProfiles, Doctors, Specialties, Clinics, DoctorSchedules, Appointments, HealthMetrics, HealthMeasurements, LabTests, LabTestResults, MedicalRecords, MedicalDocuments, Vaccinations, Allergies, ChronicConditions, Recommendations, AIConversations, AIMessages, Notifications, AccessGrants и AuditLogs.

## 2. Требования к компьютеру

- Windows 10/11.
- Node.js 20 LTS или новее: https://nodejs.org/
- PostgreSQL 14 или новее: https://www.postgresql.org/download/
- Доступ к интернету на первом запуске для `npm install`.

Проверка:
```bat
node -v
npm -v
```

## 3. Первичная настройка PostgreSQL

1. Откройте pgAdmin.
2. Подключитесь к локальному серверу PostgreSQL.
3. Создайте пустую базу данных с именем `healthhub`.
4. Убедитесь, что служба PostgreSQL запущена.

SQL-структура и демонстрационные данные применяются сервером автоматически при первом запуске API. Файлы `server/schema.sql` и `server/seed.sql` можно также выполнить вручную в Query Tool базы `healthhub`, если автоматическая инициализация завершилась ошибкой.

## 4. Настройка подключения

При первом запуске `start.bat` создаёт `server\.env` из `server\.env.example` и открывает его в Блокноте.

Пример:
```env
PORT=4000
DATABASE_URL=postgres://postgres:ВАШ_ПАРОЛЬ@localhost:5432/healthhub
JWT_SECRET=замените-на-длинный-случайный-секрет-минимум-32-символа
CLIENT_ORIGIN=http://localhost:5173
```

Замените `ВАШ_ПАРОЛЬ` на пароль пользователя PostgreSQL. Сохраните файл и закройте Блокнот. Если пароль содержит `@`, `#`, `%`, `/` или другие специальные символы, используйте URL-кодирование этих символов.

**Не публикуйте файл `.env` и не передавайте его другим людям.**

## 5. Запуск приложения

1. Убедитесь, что PostgreSQL запущен и база `healthhub` создана.
2. Запустите `start.bat` двойным щелчком.
3. При первом запуске BAT установит npm-зависимости.
4. Откроются два окна: API-сервер и веб-клиент.
5. Сервер автоматически проверит/создаст таблицы и добавит синтетические демо-данные.
6. Откройте http://localhost:5173.

Проверка API: http://localhost:4000/api/health — при корректной настройке должен вернуться JSON с `ok: true` и `database: connected`.

Окна API и Web нужно оставить открытыми. Для остановки нажмите `Ctrl+C` в каждом окне.

## 6. Демо-аккаунты

Все три аккаунта используют пароль `demo1234`:

| Роль | Email | Пароль |
|---|---|---|
| Пациент | `anna@example.test` | `demo1234` |
| Врач | `doctor@example.test` | `demo1234` |
| Администратор | `admin@example.test` | `demo1234` |

Демо-учётные записи и пароль предназначены только для локального учебного запуска. Перед публичным развёртыванием замените их и JWT-секрет.

## 7. Ручной запуск

Терминал №1:
```bat
cd server
npm install
npm run dev
```

Терминал №2:
```bat
cd client
npm install
npm run dev
```

Vite проксирует `/api` на `http://localhost:4000`, поэтому в браузере используется единый origin `http://localhost:5173`.

## 8. Проверка сценария добавления показателя

1. Войдите как пациент `anna@example.test` / `demo1234`.
2. Откройте «Мои показатели».
3. Нажмите «Добавить измерение».
4. Выберите показатель, введите значение и нажмите «Сохранить».
5. После ответа сервера появится уведомление об успешном сохранении; запись появится в таблице и обновит карточку на Dashboard.
6. Проверьте строку в PostgreSQL:
```sql
SELECT metric, value, unit, measured_at, source
FROM health_measurements
WHERE patient_id=(SELECT id FROM users WHERE email='anna@example.test')
ORDER BY measured_at DESC;
```

Если сервер не отвечает, приложение показывает сообщение об ошибке и не сообщает об успешном сохранении.

## 9. Диапазоны ручного ввода

| Показатель | Диапазон | Единица |
|---|---:|---|
| Пульс | 25–240 | уд/мин |
| SpO₂ | 50–100 | % |
| Температура | 30–45 | °C |
| Шаги | 0–100000 | шагов |
| Сон | 0–24 | ч |

Это технические границы проверки формы, а не медицинские референсные нормы.

## 10. Проверка типичных проблем

**`server\.env is missing`** — запустите `start.bat` из корневой папки распакованного проекта. Скрипт должен создать файл из `.env.example`. Если файл не появился, скопируйте его вручную.

**`ECONNREFUSED` / `password authentication failed`** — проверьте, что PostgreSQL запущен, база `healthhub` существует, а `DATABASE_URL` содержит правильные логин, пароль и порт.

**`database "healthhub" does not exist`** — создайте базу `healthhub` в pgAdmin; приложение создаёт таблицы внутри базы, но не сам кластер/базу PostgreSQL.

**Порт занят** — освободите порт 4000 или 5173. Если меняете порт API, обновите `target` в `client/vite.config.js`.

**Изменения интерфейса не отображаются** — обновите страницу браузера сочетанием `Ctrl+F5`; не закрывайте окно Vite.

**Проблема с зависимостями** — удалите `client/node_modules` и/или `server/node_modules`, затем повторно запустите `start.bat`.

## 11. Границы учебной версии

- ИИ-ассистент использует правила и заготовленные справочные ответы, не внешнюю языковую модель.
- Карта клиник показана в виде стилизованной схемы; внешний поиск по карте открывается через OpenStreetMap.
- В базе предусмотрены таблицы для документов, вакцинаций, аллергий и хронических состояний; загрузка файлов для медкарты и лабораторных результатов реализована, но отдельные CRUD-формы вакцинаций, аллергий и хронических состояний остаются направлением дальнейшего расширения.
- Мобильная версия — адаптивный веб-интерфейс (не отдельные нативные приложения для iOS/Android).
- Нельзя использовать эту учебную сборку для реальных медицинских данных или клинических решений.

## 12. Проверка сборки

В комплекте есть `check-build.bat` для проверки синтаксиса API и production-сборки веб-клиента после установки npm-зависимостей, а также `verify.bat` для проверки запущенных локальных сервисов. Отчёт о проверках, выполненных при подготовке архива, находится в `ПРОВЕРКА_СБОРКИ.txt`. Полный тест с реальным PostgreSQL нужно выполнить на компьютере, где установлен PostgreSQL.

## 13. Технологии

React, Vite, Lucide, Node.js, Express, PostgreSQL, JWT, встроенный Node.js `crypto.scrypt`.


## Исправление запуска (ошибка API / ECONNREFUSED)

Если веб-страница показывает `Ошибка запроса (500)`, а в окне Vite появляется `ECONNREFUSED`, это означает, что API не запущен или завершился при старте. Убедитесь, что служба PostgreSQL запущена и доступна по адресу из `server/.env` (`DATABASE_URL`). По умолчанию используется `postgres://postgres:postgres@localhost:5432/healthhub`. База `healthhub` должна быть создана заранее (скрипт `server/create_database.sql` запускается в pgAdmin, подключившись к базе `postgres`). После исправления настроек закройте старые окна API/Web и снова запустите `start.bat`.

В этой версии также исправлен порядок создания таблиц в `server/schema.sql`: ранее миграция пыталась изменить таблицу `notifications` до её создания, из-за чего API завершался при инициализации чистой базы.
